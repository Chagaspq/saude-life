# TOMAS DE OLIVEIRA (17)

**Tomas de Oliveira**
*Parte 2 · Demonstração · Treino guiado*
Esta é a tela do treino. A pessoa marca cada série, ajusta as repetições e a carga, e o descanso começa a contar sozinho. Cada série vale pontos.

**Tomas de Oliveira**
*Parte 2 · Demonstração · Treino: extras e resumo*
Tem também drop set, bi-set, troca de exercício e as dicas de como fazer. No final aparece o resumo: duração, séries, volume levantado e calorias, e a pessoa diz como foi o treino.

**Tomas de Oliveira**
*Parte 2 · Demonstração · Alimentação*
Na Alimentação, o app calcula as metas de calorias e de proteína. Ao adicionar uma refeição, a busca de alimentos soma os valores sozinha. E tem o controle de água com a garrafinha.

**Tomas de Oliveira**
*Parte 2 · Demonstração · Evolução*
Na Evolução ficam o gráfico do peso, os treinos por semana com a linha da meta, o histórico de treinos e as metas pessoais.

**Tomas de Oliveira**
*Parte 2 · Demonstração · Perfil*
No Perfil aparecem o tipo de conta, os objetivos, as conquistas e os lembretes. A pessoa também pode baixar ou apagar os próprios dados, pensando na LGPD.

**Tomas de Oliveira**
*Parte 2 · Demonstração · Assinatura*
E aqui a assinatura: o teste grátis de trinta dias ou a escolha de um plano pago.

**Tomas de Oliveira**
*Parte 4 · Back-end · Tecnologia*
Agora o back-end. Ele é uma API feita em Java 17 com Spring Boot. Para falar com o banco usamos o Spring Data JPA, que cria os comandos SQL a partir das nossas classes.

**Tomas de Oliveira**
*Parte 4 · Back-end · Pastas*
O código fica organizado assim: em model está a classe Usuario, que vira a tabela de usuários no banco. Em repository está o UsuarioRepository, e o Spring cria sozinho os comandos, como o findAll e o save. Em controller está o UsuarioController, com as rotas. E a conexão com o banco fica no application.properties.

**Tomas de Oliveira**
*Parte 4 · Back-end · Papel da API*
A API fica no meio do caminho: recebe o que a tela manda, confere se está tudo certo e grava ou lê no SQL Server. Depois devolve a resposta em JSON para a tela.

**Tomas de Oliveira**
*Parte 4 · Back-end · Rotas*
As rotas ficam em barra usuarios: o GET lista todos os usuários, o GET com o id busca um só, o POST cadastra, o PUT altera e o DELETE apaga.

**Tomas de Oliveira**
*Parte 4 · Back-end · Conexão com o SQL Server*
Esta linha do application.properties liga a API no SQL Server: localhost, porta mil quatrocentos e trinta e três, banco saudelife. E o ddl-auto update faz a API criar a tabela sozinha a partir da classe Usuario.

**Tomas de Oliveira**
*Parte 4 · Back-end · Validações*
A API não aceita qualquer coisa: o nome não pode ficar vazio, o e-mail tem que ser válido, a senha precisa de pelo menos oito caracteres e a data de nascimento não pode ser no futuro. Se der errado, ela devolve o erro quatrocentos com a frase do problema. E se o e-mail já existe, devolve o erro quatrocentos e nove.

**Tomas de Oliveira**
*Parte 4 · Back-end · Segurança*
A senha nunca é guardada como foi digitada: ela vira um hash com o BCrypt e não aparece no JSON que a API devolve. E o CrossOrigin só deixa o nosso site chamar a API.

**Tomas de Oliveira**
*Parte 4 · Back-end · Testando no Postman*
No Postman, o GET em barra usuarios mostra a lista em JSON, e repare que a senha não aparece. Agora um POST com um e-mail que já existe: a API devolve quatrocentos e nove, com a mensagem "Já existe um usuário com este e-mail".

**Tomas de Oliveira**
*Parte 7 · Dificuldades · Dificuldade do Tomas*
Eu sou o Tomas. A minha dificuldade foi a segurança: guardar a senha com hash e fazer a API recusar dados errados com uma mensagem clara. Aprendi como uma API protege as informações.

# RAFAEL (PH) SANTOS (15)

**Rafael Santos**
*Parte 3 · Front-end · Tecnologias e pastas*
Agora o front-end. Ele foi feito em React, com HTML, CSS e JavaScript, usando o Vite para rodar e gerar o site e o React Router para trocar de tela. O código fica na pasta src: em páginas, uma tela por arquivo; em componentes, as peças reaproveitadas; o main e o rotas, que começam o app; e em estilos, o CSS.

**Rafael Santos**
*Parte 3 · Front-end · O que é um componente*
Um componente React é uma função que devolve um pedaço da tela e pode ser reaproveitado. Este é o CartaoNumero: ele recebe o rótulo, o valor, o detalhe e o ícone, e monta o cartão. A mesma peça aparece no Início, na Evolução, no resumo do treino e no painel do administrador.

**Rafael Santos**
*Parte 3 · Front-end · Componente em uso*
Aqui ele sendo usado no Início. Basta chamar o componente com textos diferentes: meta da semana, sequência, treinos realizados e tempo treinado. Se mudarmos o visual do cartão em um lugar, muda em todas as telas.

**Rafael Santos**
*Parte 3 · Front-end · Rotas com o React Router*
O app tem um index html só. No arquivo rotas, cada endereço mostra uma tela, como barra login ou barra app barra início, e o Link troca de tela sem recarregar a página. O controle de quem pode abrir cada tela fica no AppLayout: sem login, a pessoa vai para a tela de entrar, e o cliente não abre o painel do administrador.

**Rafael Santos**
*Parte 3 · Front-end · CSS e responsividade*
O CSS organiza o layout. As cores e os espaços ficam em variáveis, e as media queries mudam a tela conforme a largura: abaixo de novecentos pixels aparece o menu embaixo, como num aplicativo de celular. E cada tela carrega o próprio CSS, para uma não atrapalhar a outra.

**Rafael Santos**
*Parte 3 · Front-end · No celular*
E aqui o mesmo Início no tamanho de um celular. A tela se reorganiza sozinha: os cartões ficam um embaixo do outro e o menu de baixo dá acesso às cinco abas.

**Rafael Santos**
*Parte 6 · Fluxo completo · 1. O usuário clica*
Agora uma funcionalidade do começo ao fim: cadastrar um usuário. Na tela de usuários, eu clico em Novo Usuário, preencho o nome, o e-mail, a senha, o tipo e a data de nascimento, e clico em Salvar. Esse botão chama a função salvar do FormularioUsuario.

**Rafael Santos**
*Parte 6 · Fluxo completo · 2. O front envia*
O front manda os dados para a API. No usuarioService, a função criarUsuario faz um fetch do tipo POST em barra usuarios, com os dados em JSON.

**Rafael Santos**
*Parte 6 · Fluxo completo · 3. A API valida e grava*
A API recebe no UsuarioController, no método criar. Ela confere os dados, vê se o e-mail já existe, transforma a senha em hash e chama o save do repositório, que faz o INSERT no banco.

**Rafael Santos**
*Parte 6 · Fluxo completo · 4. O SQL Server grava*
No SQL Server, o SELECT na tabela de usuários já mostra o usuário que acabou de ser cadastrado.

**Rafael Santos**
*Parte 6 · Fluxo completo · 5. A tela atualiza*
A API devolve o código duzentos e um com o usuário salvo, sem a senha, e a tela mostra "Usuário criado com sucesso", já com ele na lista. Dá também para editar no lápis e apagar no X. Tela, API e banco funcionando juntos.

**Rafael Santos**
*Parte 7 · Dificuldades · Dificuldade do Rafael*
Eu sou o Rafael. A minha dificuldade foi passar o site, que tinha várias páginas HTML, para um app React só, com React Router, sem mudar o visual. Aprendi a dividir a tela em componentes e a reaproveitar o código.

## Como gravar

1. Cada um grava **o rosto e a voz** lendo as próprias falas (pode ser no celular, de frente, com boa luz).
2. No editor (CapCut, Clipchamp, Premiere...), coloque o vídeo da tela por baixo e o **vídeo do rosto** de quem está falando no quadrado à direita: **posição x = 1472, y = 32, tamanho 416 × 416** (num vídeo 1920 × 1080).
3. Monte na ordem das partes (1 a 8), não na ordem deste arquivo: aqui as falas estão agrupadas por pessoa só para cada um ensaiar as suas.
